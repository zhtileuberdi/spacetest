# Материалы для курсовой: «Приложение для создания и сдачи онлайн-тестов» (TestSpace)

## 1. Цель и задачи
**Цель:** разработать веб-приложение, в котором учитель создаёт тесты и задачи по программированию, а студенты выполняют их под контролем системы защиты от списывания.
**Задачи:** анализ аналогов (Google Forms, Moodle, Яндекс.Контест) → проектирование → реализация клиента и облачного бэкенда (Firebase) → автоматическая проверка кода → защита от списывания → тестирование.

## 2. Технологии (с обоснованием)
* **Firebase Authentication + Cloud Firestore (BaaS)** — вход и база данных как готовый облачный сервис: свой сервер не нужен, сайт состоит из статических файлов и размещается на **Vercel**.
* **Vanilla JS + HTML/CSS** — лёгкий интерфейс без сборки; Canvas для 3D-сферы на главной.
* **Firestore Security Rules** — правила доступа к данным на стороне Firebase (кто что читает и пишет), заменяют проверки серверного кода.
* **Web Worker и Pyodide (Python в WebAssembly)** — запуск JavaScript и Python прямо в браузере с таймаутом для проверки решений.
* **Fullscreen API, Page Visibility API, Clipboard events** — основа защиты от списывания.
* **Firebase Auth** — безопасное хранение паролей (хеширование на стороне Google).

## 3. Модель данных
| Сущность | Поля |
|---|---|
| users | id (= uid в Firebase Auth), name, username, role (teacher/student/user), joined[] (приватные задания, открытые по коду) |
| groups / groupMembers / groupKeys | группа (name, teacher); участник (groupId, uid); ключ входа = SHA-256(название + пароль) → группа |
| tests / testQuestions / testSecrets | карточка (teacher, access, groupId, deadline, title, timerMode, minutes, mode); вопросы без ответов; секреты (верные ответы, скрытые тесты, код) |
| questions | type (mc/code), text, image (фото), options, correct, lang, tests[{input, expected, hidden}], hint, starter |
| attempts | id = testId_studentId, variant, startedAt (время сервера), answers (автосохранение), violations[{type, at}], auto, bonus, finished, expired |
| testCodes, images | код приватного теста → тест; фото вопросов |

## 4. Алгоритмы
1. **Проверка кода:** для каждого теста — запуск программы в браузере (Web Worker / Pyodide) с входными данными, сравнение вывода с ожидаемым (нормализация пробелов/переводов строк), таймаут против зависаний. Java и C++ требуют компилятора и проверяются учителем вручную.
2. **Подсчёт результата:** доля пройденных тестов по каждой задаче + тестовые вопросы; учитель может добавить баллы вручную.
3. **Антиплагиат (антисписывание):** события `fullscreenchange`, `visibilitychange`, `blur`, `paste/copy/cut/drop/contextmenu`, Ctrl+V → нарушение → Монстр → запись в Firestore → онлайн-контроль у учителя (живая подписка onSnapshot). На 3-м нарушении работа сдаётся автоматически.
4. **Срок сдачи:** дедлайн хранится в карточке теста; время старта и текущее время берутся с сервера Firebase (защита от перевода часов на ПК). Просроченные работы закрываются с сохранёнными ответами и проверяются автоматически при открытии списков и панели учителя либо при следующем входе студента.
4а. **Защита ответов:** правила Firestore не отдают студенту верные ответы и скрытые тесты, пока он не сдал работу; пароль группы хранится только как хеш-ключ.
5. **Доступ к заданию:** group — только участники группы; public — виден в каталоге всем; private — открывается по коду (код добавляет задание в список пользователя).
6. **Автодополнение:** по префиксу слова ищутся ключевые слова языка и шаблоны (`for`, `if`, `while`, `main`).

## 5. Роли и сценарии (для диаграмм use-case)
Учитель: группы → тесты → онлайн-контроль → статистика/оценка. Студент: вступление → правила → выполнение → результат.

## 6. План тестирования (таблица для главы «Тестирование»)
| № | Сценарий | Ожидаемый результат |
|---|---|---|
| 1 | Регистрация с паролем < 4 символов | ошибка |
| 2 | Вход с неверным паролем | отказ |
| 3 | Вступление в группу с неверным паролем | отказ |
| 4 | Esc во время теста | Монстр на весь экран, нарушение 1/3 |
| 5 | Ctrl+V в редакторе | Монстр, вставка заблокирована |
| 6 | Три нарушения | автосдача работы |
| 7 | Код с синтаксической ошибкой | ошибка и номер строки |
| 8 | Бесконечный цикл | остановка по таймауту (3 с) |
| 9 | Сдача теста | результат в % у студента и в статистике учителя |
| 10 | Приватное задание, вход по неверному коду | отказ; по верному коду задание появляется в списке |
| 11 | Задание со сроком сдачи, студент не успел | работа закрывается с тем, что он написал |
| 11а | Приватное задание: старт без кода | отказ (доступ закрыт правилами Firestore) |
| 12 | Ввод верного кода | задание появляется в списке |
| 13 | Публичное задание в каталоге | видно всем, приватное не видно |
| 14 | Срок сдачи прошёл | работа закрыта автоматически, ответы сохранены |
| 15 | Вопрос с фото | фото видно студенту |

## 7. Возможные направления развития
проверка работ на сервере (Cloud Functions) для защиты от подделки оценки, запуск Java/C++ через внешний сервис компиляции, вопросы с несколькими ответами, экспорт в Excel, прокторинг через камеру.
